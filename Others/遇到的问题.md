
## 最可能是你说的那次：训练中途 loss 反常上升

在 [05_true_lmc.ipynb](src/05_true_lmc.ipynb) 早期版本里，训练日志出现过这样的情况：

```
iter 200: loss=0.9329
iter 400: loss=0.9471   ← 比第200步还差，训练"变差"了
iter 600: loss=0.9426
```

**这确实是"训练效果不好"的直接表现**——本该越训越好的 loss，中途竟然升高了。当时误以为是学习率没调好，还专门加了余弦退火调度器去"压制震荡"。但后来发现根本原因不在优化过程本身，而在**评估这个 loss 的方式本身带噪声**——用的是近似计算（CG + 随机 Lanczos），同一组参数重新算一次都会得到不同的数字，噪声幅度大概 0.0095。所以不是模型训练得不好，是"用来判断训练好不好的这把尺子本身在抖动"。

## 完整的问题时间线

| 顺序 | 问题                            | 表现                                                                                        |
| ---- | ------------------------------- | ------------------------------------------------------------------------------------------- |
| 1    | `05_true_lmc.ipynb` 是空文件  | 产生早期结果的代码丢失了，0字节                                                             |
| 2    | **数值精度**（上面那个）  | 训练loss震荡、不单调，同参数重算结果不同                                                    |
| 3    | 类名误标：`LMCModel`实际是ICM | 交叉验证Q=1时才发现命名和实现对不上                                                         |
| 4    | "lengthscale崩塌"误判           | 用错参照系（0.27km是算错的密度估计），一度以为模型退化成了逐点回归                          |
| 5    | **`best_loss`挑最小值** | 在带噪声的loss序列里取最小值，等于"挑运气最好的一次"，导致选错Q（先选Q=3，又选Q=4，都不对） |
| 6    | 用训练似然选模型                | 似然会随参数增多单调变好，永远选到最复杂的模型，必须换用BIC/AIC                             |
| 7    | rank敏感性"测不出差异"          | 一开始以为是噪声，后来证明是数学恒等式（rank=1已经张满自由度）                              |
| 8    | **图存出来是空白的**      | `plt.show()`写在`plt.savefig()`之前，导致保存的PNG是空的（只有3.4KB）                   |
| 9    | 编辑器覆盖了修改                | 在VS Code里改了标题并保存，把我之前用工具改好的7处内容全部覆盖回旧版本                      |
| 10   | matplotlib版本不兼容            | `boxplot(labels=...)`参数在新版本里改名了，脚本直接报错退出                               |

## 哪个最值得写进演讲/报告

如果你说的"效果不好"就是指第2条（训练loss震荡），**这个其实是今天演讲稿第9页故事里的核心情节**——正是因为发现了这个异常，才一步步追查到数值精度问题，进而修正了整个模型选择的结论。

如果你想到的是别的场景，可以再形容一下当时的具体现象（比如是RMSE很差、还是loss不降、还是图不对），我帮你定位是哪一次。
